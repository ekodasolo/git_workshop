# 第7章：コンフリクトの理解と対応

この章では、ブランチのマージ時に発生する「コンフリクト（競合）」の仕組みと、手動で解消する手順を学びます。初心者が最も不安に感じるテーマですが、手順通りにやれば解消できます。

---

## 7-1. コンフリクトとは

### コンフリクトが発生する条件

コンフリクトは、**同じファイルの同じ箇所を別々のブランチで異なる内容に変更した**場合に発生します。

```
main          ──●── 価格を1,300円に変更 ──●── マージしようとすると...
                 \                         ↑
update-menu    　 ●── 価格を1,500円に変更 ──/ コンフリクト発生!
```

Gitは「どちらの変更を採用すべきか」を自動で判断できないため、人間に判断を求めます。

### 実際の開発でコンフリクトが起きるケース

コンフリクトは「誰かが間違えたから起きる」ものではなく、チームで並行作業していれば自然に起こりえます。よくあるケースを紹介します。

- **作業範囲の重複** — Aさんがバグ修正で触ったファイルの同じ箇所を、Bさんが機能改善で変更していた
- **ブランチの長期化** — トピックブランチでの作業が長引き、その間にmainが進んだ。変更箇所が重なる確率は時間とともに上がる
- **共通ファイルの編集** — 設定ファイルやREADMEなど、複数人が触りやすいファイルは衝突しやすい

### コンフリクトマーカーの読み方

コンフリクトが発生すると、対象のファイルにマーカーが挿入されます。

```
<<<<<<< HEAD
**¥1,300**
=======
**¥1,500**
>>>>>>> update-menu
```

| マーカー | 意味 |
|---|---|
| `<<<<<<< HEAD` | 現在のブランチ（マージ先）の変更内容の開始 |
| `=======` | 2つの変更の区切り |
| `>>>>>>> update-menu` | マージ元のブランチの変更内容の終了 |

解消するには、マーカーを含む部分を「最終的にどうしたいか」の内容に書き換えます。

## 7-2. コンフリクトへの対応

### 実習：意図的にコンフリクトを起こして解消する

#### 手順1：トピックブランチを作成して価格を変更する

まず、mainブランチにいることを確認してください。

```bash
git branch
```

> **補足：** 第2章の実習で¥1,200から¥1,250に変更しているため、現在の価格は¥1,250です。

トピックブランチを作成します。

```bash
git switch -c update-menu
```

burgers.md を開き、クラシックバーガーの価格を変更してください。

変更前：

```markdown
**¥1,250**
```

変更後：

```markdown
**¥1,500**
```

```bash
git add burgers.md
git commit -m "クラシックバーガーの価格を1,500円に変更"
```

#### 手順2：mainブランチに戻って同じ箇所を変更する

```bash
git switch main
```

burgers.md を開き、クラシックバーガーの価格を変更してください。

> **補足：** mainブランチに戻ると、ファイルの内容はmainの状態（¥1,250）に戻ります。update-menuブランチでの変更（¥1,500）は反映されていません。

変更前：

```markdown
**¥1,250**
```

変更後：

```markdown
**¥1,300**
```

```bash
git add burgers.md
git commit -m "クラシックバーガーの価格を1,300円に変更"
```

---

ここまでの状態を整理します。

- **mainブランチ：** クラシックバーガーの価格が ¥1,300
- **update-menuブランチ：** クラシックバーガーの価格が ¥1,500

同じファイルの同じ行を異なる内容に変更したため、マージするとコンフリクトが発生します。

---

#### 手順3：mainブランチでマージする

すでにmainブランチにいるので、そのままマージします。

```bash
git merge update-menu
```

### 期待される出力

```
Auto-merging burgers.md
CONFLICT (content): Merge conflict in burgers.md
Automatic merge failed; fix conflicts and then commit the result.
```

> **補足：** `CONFLICT` と表示され、自動マージが失敗したことがわかります。この時点ではマージは完了しておらず、コンフリクトの解消を待っている状態です。

#### 手順4：状態を確認する

```bash
git status
```

### 期待される出力

```
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
        both modified:   burgers.md

no changes added to commit (use "git add" to track)
```

> **補足：** `both modified` は「両方のブランチで変更された」ことを示しています。

#### 手順5：コンフリクトマーカーを確認する

burgers.md を開いてください。クラシックバーガーの価格部分に、以下のようなコンフリクトマーカーが挿入されています。

```
<<<<<<< HEAD
**¥1,300**
=======
**¥1,500**
>>>>>>> update-menu
```

#### 手順6：コンフリクトを手動で解消する

今回は ¥1,500 を採用することにします。コンフリクトマーカーを含む部分を以下のように書き換えてください。

```markdown
**¥1,500**
```

> **重要：** `<<<<<<< HEAD`、`=======`、`>>>>>>> update-menu` のマーカー行もすべて削除してください。最終的に残るのは採用する内容だけです。

#### 手順7：解消をGitに伝えてマージを完了する

```bash
git add burgers.md
git commit -m "コンフリクトを解消：クラシックバーガーの価格を1,500円に統一"
```

> **補足：** コンフリクトの解消は `git add` で「解消済み」とマークし、`git commit` でマージコミットを作成することで完了します。

#### 手順8：履歴を確認する

```bash
git log --oneline -5
```

### 期待される出力

```
xxxxxxx (HEAD -> main) コンフリクトを解消：クラシックバーガーの価格を1,500円に統一
xxxxxxx (update-menu) クラシックバーガーの価格を1,500円に変更
xxxxxxx クラシックバーガーの価格を1,300円に変更
xxxxxxx Revert "スモークベーコンバーガーを追加"
xxxxxxx スモークベーコンバーガーを追加
```

#### 手順9：ブランチを削除してプッシュする

```bash
git branch -d update-menu
git push
```

## 7-3. マージの中止 — git merge --abort

コンフリクトが発生した際に「やっぱりマージをやめたい」と思った場合は、`git merge --abort` でマージ前の状態に戻せます。

```bash
git merge --abort
```

> **補足：** このコマンドはコンフリクトの解消を始める前に実行してください。すでにファイルを編集してしまった場合でも使えますが、編集内容は失われます。実際の開発では「コンフリクトの量が多すぎて対応しきれない」「そもそもマージすべきでなかった」といった場合に使います。

---

## 7-4. revert 時のコンフリクト（参考）

第6章で学んだ `git revert` を実行した際にもコンフリクトが発生することがあります。revert対象のコミット以降に同じ箇所が変更されている場合です。

対処方法はマージ時と同じで、コンフリクトマーカーを確認して手動で解消し、`git add` → `git commit` で完了します。中止したい場合は `git revert --abort` が使えます。

---

## この章のまとめ

この章で学んだ内容は以下の通りです。

| コマンド・操作 | 用途 |
|---|---|
| コンフリクトマーカーの手動編集 | コンフリクトを解消する |
| `git add` → `git commit` | コンフリクト解消後にマージを完了する |
| `git merge --abort` | マージを中止してコンフリクト発生前に戻る |

### コンフリクト解消の手順まとめ

```
1. git merge ブランチ名         ← コンフリクト発生
2. git status                  ← 対象ファイルを確認
3. ファイルを開いてマーカーを編集  ← どちらを採用するか判断
4. git add ファイル名            ← 解消済みとしてマーク
5. git commit -m "メッセージ"   ← マージコミットを作成
```
