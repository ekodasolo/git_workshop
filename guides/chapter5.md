# 第5章：コミット後のやり直し（プッシュ前）

この章では、コミットした後に「やっぱり直したい」と思った場合のやり直し方法を学びます。第2章で学んだ3層構造（ワークツリー・ステージングエリア・Gitディレクトリ）の理解がここで活きてきます。

> **重要：** この章で扱う操作はすべて「まだリモートにプッシュしていないコミット」が対象です。プッシュ後のやり直しは次の第6章で扱います。

---

## 5-1. 直前のコミットの修正 — git commit --amend

「さっきのコミット、ちょっと直したい」という場面で使う、最も軽量なやり直し操作です。

---

### 実習1：コミットメッセージを修正する

#### 手順1：burgers.md に新メニューを追加する

burgers.md を開き、スパイシーチリバーガーのセクションの下（`---` と `[← トップに戻る]` の間）に以下を追加してください。

```markdown

## ダブルチーズバーガー

チェダーチーズとゴーダチーズの2種類をたっぷり使用。チーズ好きにはたまらない贅沢な一品。

**¥1,500**

---
```

#### 手順2：コミットする

```bash
git add burgers.md
git commit -m "ダブルチーズバーバーを追加"
```

> ここで「バーガー」を「バーバー」と誤って入力してしまった設定です。

#### 手順3：コミットメッセージを修正する

```bash
git commit --amend -m "ダブルチーズバーガーを追加"
```

#### 手順4：修正されたことを確認する

```bash
git log --oneline -1
```

### 期待される出力

```
xxxxxxx (HEAD -> main) ダブルチーズバーガーを追加
```

> **補足：** `--amend` は直前のコミットを「修正」します。新しいコミットが作られるのではなく、直前のコミットが置き換えられます。

---

### 実習2：コミットにファイルを追加し忘れた場合

#### 手順1：README.md にメニュー説明を追記する

本来、先ほどのコミットでREADME.mdのメニューセクションにあるバーガーメニューの説明も更新すべきだったとします。README.md のメニューセクションで、バーガーメニューの行を以下のように変更してください。

変更前：

```markdown
- [バーガーメニュー](burgers.md) — 自慢のグルメバーガーをご紹介
```

変更後：

```markdown
- [バーガーメニュー](burgers.md) — 自慢のグルメバーガーをご紹介（新メニューあり）
```

#### 手順2：直前のコミットに含める

```bash
git add README.md
git commit --amend --no-edit
```

#### 手順3：確認する

```bash
git log --oneline -1
git show --stat HEAD
```

### 期待される出力

```
xxxxxxx (HEAD -> main) ダブルチーズバーガーを追加
```

```
commit xxxxxxx (HEAD -> main)
Author: ...
Date:   ...

    ダブルチーズバーガーを追加

 README.md  | 2 +-
 burgers.md | 8 ++++++++
 2 files changed, 9 insertions(+), 1 deletion(-)
```

> **補足：** `--no-edit` オプションを付けると、コミットメッセージを変更せずにファイルだけを追加できます。`git show --stat HEAD` で、直前のコミットに含まれるファイルを確認できます。

---

## 5-2. コミットの取り消し — git reset

`git commit --amend` は直前のコミットの「微修正」でした。`git reset` はもっと大きく、コミット自体を取り消す操作です。

### git reset の3つのモード

`git reset` には3つのモードがあり、3層構造のどこまで巻き戻すかが異なります。

```
                         --soft    --mixed   --hard
                        ┌────────┬─────────┬────────┐
  Gitディレクトリ       │ 巻き戻す│ 巻き戻す │ 巻き戻す│
  (コミット履歴)        │        │         │        │
                        ├────────┼─────────┼────────┤
  ステージングエリア     │ そのまま│ 巻き戻す │ 巻き戻す│
                        │        │         │        │
                        ├────────┼─────────┼────────┤
  ワークツリー          │ そのまま│ そのまま │ 巻き戻す│
  (作業ディレクトリ)     │        │         │        │
                        └────────┴─────────┴────────┘
```

| モード | コミット履歴 | ステージングエリア | ワークツリー | 主な用途 |
|---|---|---|---|---|
| `--soft` | 巻き戻す | そのまま | そのまま | ステージングに残したまま、コミットだけやり直したい |
| `--mixed`（デフォルト） | 巻き戻す | 巻き戻す | そのまま | ステージングするファイルを選び直したい |
| `--hard` | 巻き戻す | 巻き戻す | 巻き戻す | 変更自体が不要になり、すべて元に戻したい |

> **補足：** `HEAD~1` は「直前のコミットの1つ前」を意味します。`HEAD~2` なら2つ前です。

---

### 実習1：--soft モードを体験する

コミットした直後に「このファイルも一緒にコミットすべきだった」と気づいた。変更はすべてステージングに残したまま、コミットだけ取り消してやり直したいときに使います。

#### 手順1：現在の状態を確認する

```bash
git log --oneline -3
```

直前のコミットが「ダブルチーズバーガーを追加」であることを確認してください。

#### 手順2：--soft で1つ前に戻す

```bash
git reset --soft HEAD~1
```

> **補足：** `HEAD` は今いるコミット（取り消したいコミット）、`HEAD~1` はその1つ前のコミットを意味します。つまり「`HEAD~1` に戻す」＝「直前のコミットをなかったことにする」ということです。

#### 手順3：状態を確認する

```bash
git log --oneline -3
git status
```

### 期待される出力

```
xxxxxxx (HEAD -> main) 店舗情報を追加
xxxxxxx ドリンクメニューを追加
xxxxxxx サイドメニューを追加
```

```
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        modified:   README.md
        modified:   burgers.md
```

> **補足：** コミットは消えましたが、変更内容はステージングエリアに残っています。すぐに `git commit` すれば、メッセージを変えて再コミットできます。

#### 手順4：再コミットして元に戻す

次の実習のために再コミットしておきます。

```bash
git commit -m "ダブルチーズバーガーを追加"
```

---

### 実習2：--mixed モードを体験する

関係のないファイルまでまとめてコミットしてしまった。コミットを取り消して、ステージングするファイルを選び直したいときに使います。

#### 手順1：--mixed で1つ前に戻す

```bash
git reset --mixed HEAD~1
```

> **補足：** `--mixed` はデフォルトなので、`git reset HEAD~1` と書いても同じです。

#### 手順2：状態を確認する

```bash
git log --oneline -3
git status
```

### 期待される出力

```
xxxxxxx (HEAD -> main) 店舗情報を追加
xxxxxxx ドリンクメニューを追加
xxxxxxx サイドメニューを追加
```

```
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   README.md
        modified:   burgers.md

no changes added to commit (use "git add" to track)
```

> **補足：** `--soft` との違いに注目してください。変更内容はワークツリーに残っていますが、ステージングエリアからは外れています。`git add` からやり直す必要があります。

#### 手順3：再コミットして元に戻す

```bash
git add -A
git commit -m "ダブルチーズバーガーを追加"
```

---

### 実習3：--hard モードを体験する

試しに書いてみたコードがうまくいかず、変更自体が不要になった。ファイルの内容ごとすべてを元に戻したいときに使います。

#### 手順1：--hard で1つ前に戻す

```bash
git reset --hard HEAD~1
```

### 期待される出力

```
HEAD is now at xxxxxxx 店舗情報を追加
```

#### 手順2：状態を確認する

```bash
git log --oneline -3
git status
```

### 期待される出力

```
xxxxxxx (HEAD -> main) 店舗情報を追加
xxxxxxx ドリンクメニューを追加
xxxxxxx サイドメニューを追加
```

```
On branch main
nothing to commit, working tree clean
```

> **補足：** コミット履歴・ステージングエリア・ワークツリーのすべてが巻き戻されました。burgers.mdを開くと、ダブルチーズバーガーの追加がなくなっていることが確認できます。`--hard` は変更が完全に失われるため、慎重に使ってください。

---

## 5-3. なぜプッシュ前に限定するのか

`git commit --amend` と `git reset` はどちらもコミット履歴を書き換える操作です。

ローカルだけで作業している間は問題ありませんが、すでにリモートにプッシュした内容に対してこれらの操作を行うと、リモートとローカルの履歴が食い違い、チームメンバーとの間で深刻な問題が発生します。

**ルール：履歴の書き換えは、プッシュ前のコミットに対してのみ行う。**

では、プッシュ後に「やっぱり取り消したい」と思った場合はどうするのか？ それが次の章で学ぶ `git revert` です。

---

## この章のまとめ

この章で学んだコマンドは以下の通りです。

| コマンド | 用途 |
|---|---|
| `git commit --amend -m "メッセージ"` | 直前のコミットメッセージを修正 |
| `git commit --amend --no-edit` | 直前のコミットにファイルを追加（メッセージは変更しない） |
| `git reset --soft HEAD~1` | コミットを取り消す（変更はステージングに残る） |
| `git reset --mixed HEAD~1` | コミットとステージングを取り消す（変更はワークツリーに残る） |
| `git reset --hard HEAD~1` | コミット・ステージング・ワークツリーすべてを巻き戻す |
| `git show --stat HEAD` | 直前のコミットに含まれるファイルを確認 |

### やり直し操作の使い分け（ここまでのまとめ）

| やりたいこと | コマンド | 学んだ章 |
|---|---|---|
| ワークツリーの変更を取り消したい | `git restore` | 第2章 |
| ステージングを取り消したい | `git restore --staged` | 第2章 |
| 直前のコミットを微修正したい | `git commit --amend` | 第5章 |
| コミットを取り消したい（変更は残す） | `git reset --soft` / `--mixed` | 第5章 |
| コミットを完全になかったことにしたい | `git reset --hard` | 第5章 |
| プッシュ済みの変更を取り消したい | `git revert`（次章） | 第6章 |
