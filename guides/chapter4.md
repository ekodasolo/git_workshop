# 第4章：ブランチの基本

この章では、ブランチの概念と操作方法を学びます。ブランチ戦略の全体像を理解したうえで、トピックブランチの作成・マージを繰り返し体験します。

---

## 4-1. ブランチとは

### なぜブランチを使うのか

第2章で、コミットは「変更の記録」だと学びました。コミットを重ねていくと、それは変更の歴史になります。

```
●──●──●──●    コミットの連なり = 変更の歴史
```

ここで「新メニューを追加したいが、うまくいかなければ元に戻すかもしれない」という場面を考えてみましょう。歴史の本流に直接手を入れると、失敗したときの影響が大きくなります。

そこで、歴史を枝分かれさせます。これがブランチです。文字通り「枝」という意味です。

```
main        ──●──●──●──●
                        \
feature                  ●──●    枝分かれした歴史
```

枝の上で自由に試行錯誤できます。うまくいったら、歴史の本流に合流させます（マージ）。うまくいかなければ、枝を捨てるだけで本流は無傷です。

```
main        ──●──●──●──●─────────●    合流（マージ）
                        \       ↑
feature                  ●──●──/
```

その間も、本流では他のメンバーが別の作業を進められます。第3章のチーム作業と同じ考え方です。自分が枝で新メニューを試している間に、Aさんは本流で別の修正をコミットしている、ということが自然にできます。

このように、ブランチには2つの役割があります。

- **統合ブランチ（main）：** 常に正しい状態を保つ「幹」
- **トピックブランチ（feature）：** 特定の作業のために分岐する「枝」

作業が完了したらトピックブランチを統合ブランチにマージ（合流）し、不要になったブランチを削除します。

### ここまでの概念の整理

| 概念 | 意味 |
|---|---|
| コミット | ファイルの状態を記録した1つの「点」。コミットを重ねると変更の歴史になる |
| ブランチ | 歴史を枝分かれさせる仕組み。本流に影響を与えずに作業できる |
| マージ | 枝分かれした歴史を本流に合流させる操作。作業が完了したら統合する |

```
         コミット    ブランチ(枝分かれ)       マージ(合流)

main     ──●──●──●──●───────────────────●
                    \                  ↑
feature              ●──●──●──●──●───/
                     コミットを重ねて作業
```

この3つがGitでの共同作業の基本的な仕組みです。ここから先は、具体的なコマンドと操作に入っていきます。

## 4-2. ブランチ戦略の概要 — Git Flowを知る

### なぜ運用ルールが必要なのか

ブランチは自由に作れるため、ルールなしに使うと「どのブランチが最新なのかわからない」「マージの順序が混乱する」といった問題が起きます。そこで、ブランチの使い方を定めた「ブランチ戦略」が必要になります。

### Git Flowの全体像

代表的なブランチ戦略であるGit Flowでは、5種類のブランチを使い分けます。

```
main        ──●──────────────────────●──●── (本番リリース)
               \                    ↑   ↑
release     　  \            ──●──●/    |   (リリース準備)
                 \          /           |
develop     ──●───●──●──●──●──●─────●──/ (開発の統合)
                   \      ↑    \    ↑
feature     　      ●──●─/      ●──/ (機能開発)
                                ↑
hotfix      ────────────────── ●──      (緊急修正)
```

| ブランチ | 役割 |
|---|---|
| main | 本番リリースの状態を保持する |
| develop | 開発中の最新状態を統合する |
| feature | 個別の機能を開発する |
| release | リリース前の最終調整を行う |
| hotfix | 本番の緊急バグを修正する |

### 今回の講座での範囲

Git Flowは大規模プロジェクト向けの戦略です。今回の講座では、**mainブランチ（統合ブランチ）とfeatureブランチ（トピックブランチ）の2つの関係に絞って体験します。**

> **参考：** Git Flow以外にも、GitHub FlowやGitLab Flowといったよりシンプルな戦略があります。今回の講座で体験する「featureブランチで作業 → mainにマージ」という流れはGitHub Flowに近い形です。ブランチ戦略に唯一の正解はなく、チームの規模や開発スタイルに合わせて選択します。

## 4-3. ブランチ操作の基本コマンド

ブランチ操作で使う主なコマンドを確認します。

| コマンド | 用途 |
|---|---|
| `git branch` | ブランチの一覧を表示 |
| `git branch ブランチ名` | ブランチを作成（切り替えはしない） |
| `git switch ブランチ名` | ブランチを切り替え |
| `git switch -c ブランチ名` | ブランチの作成と切り替えを同時に行う |

> **参考：** 以前は `git checkout` がブランチの切り替えに使われていましたが、`git checkout` はファイルの復元にも使われるため役割が曖昧でした。Git 2.23以降では、ブランチ切り替え専用の `git switch` と、ファイル復元専用の `git restore` に分離されています。本講座では `git switch` を使用します。

## 4-4. トピックブランチの作成とマージ

ここからが実習の本番です。featureブランチを作成してファイルを追加し、mainにマージする流れを3回繰り返します。

---

### サイクル1：サイドメニューの追加

#### 手順1：トピックブランチを作成して切り替える

```bash
git switch -c add-sides
```

#### 期待される出力

```
Switched to a new branch 'add-sides'
```

#### 手順2：現在のブランチを確認する

```bash
git branch
```

#### 期待される出力

```
* add-sides
  main
```

> **補足：** `*` が付いているブランチが現在のブランチです。

#### 手順3：sides.md を作成する

Code Serverで `sides.md` を新規作成し、以下の内容を入力してください。

```markdown
# サイドメニュー

バーガーのお供にぴったりなサイドメニューを取り揃えています。

---

## フレンチフライ

カリッと揚げたホクホクのフライ。ケチャップとマスタードを添えてどうぞ。

**¥400**

---

## オニオンリング

甘みのある玉ねぎにサクサクの衣をまとわせました。ビールとの相性も抜群です。

**¥450**

---

## コールスロー

シャキシャキのキャベツとにんじんを自家製ドレッシングで和えたさっぱりとした一品。

**¥350**

---

## チリチーズフライ

フレンチフライに自家製チリソースとチェダーチーズをたっぷりかけた、ボリューム満点のサイドメニュー。

**¥550**

---

> バーガーメニューは [こちら](burgers.md) からどうぞ。
>
> お飲み物は [ドリンクメニュー](drinks.md) をご覧ください。

[← トップに戻る](README.md)
```

#### 手順4：README.md にサイドメニューへのリンクを追加する

README.md のメニューセクションに以下の行を追記してください。

```markdown
- [サイドメニュー](sides.md) — バーガーのお供にぴったり
```

追記後のメニューセクション：

```markdown
## メニュー

- [バーガーメニュー](burgers.md) — 自慢のグルメバーガーをご紹介
- [サイドメニュー](sides.md) — バーガーのお供にぴったり
```

#### 手順5：変更をコミットする

```bash
git add -A
git commit -m "サイドメニューを追加"
```

#### 手順6：mainブランチに切り替えてマージする

```bash
git switch main
git merge add-sides
```

#### 期待される出力

```
Updating xxxxxxx..xxxxxxx
Fast-forward
 README.md |  1 +
 sides.md  | 43 +++++++++++++++++++++++++++++++++++++++++++
 2 files changed, 44 insertions(+)
 create mode 100644 sides.md
```

> **補足：** 「Fast-forward」は、mainブランチがadd-sidesブランチに追いつくだけで済む（分岐が発生していない）場合のマージ方法です。履歴が一直線のまま進みます。

#### 手順7：マージ済みのブランチを削除する

```bash
git branch -d add-sides
```

#### 期待される出力

```
Deleted branch add-sides (was xxxxxxx).
```

#### 手順8：プッシュする

```bash
git push
```

## 4-5. 実習の成果を確認する

3サイクルの実習が完了した時点で、リポジトリの状態を確認しましょう。

### 手順1：ファイル一覧を確認する

```bash
ls
```

### 期待される出力

```
README.md  burgers.md  drinks.md  info.md  sides.md
```

### 手順2：ブランチの状態を確認する

```bash
git branch
```

### 期待される出力

```
* main
```

> **補足：** トピックブランチはすべて削除済みで、mainブランチだけが残っています。

### 手順3：コミット履歴を確認する

```bash
git log --oneline
```

### 期待される出力

```
xxxxxxx (HEAD -> main, origin/main) 店舗情報を追加
xxxxxxx ドリンクメニューを追加
xxxxxxx サイドメニューを追加
xxxxxxx クラシックバーガーの価格を更新
xxxxxxx バーガーメニューを追加
xxxxxxx 最初のコミット：README.mdを作成
```

> **補足：** `git log --oneline` はコミット履歴を1行ずつ表示する省略形式です。全体の流れを俯瞰するのに便利です。

## この章のまとめ

この章で学んだコマンドは以下の通りです。

| コマンド | 用途 |
|---|---|
| `git branch` | ブランチの一覧表示 |
| `git switch -c ブランチ名` | ブランチの作成と切り替え |
| `git switch ブランチ名` | ブランチの切り替え |
| `git merge ブランチ名` | 現在のブランチに指定ブランチをマージ |
| `git branch -d ブランチ名` | マージ済みブランチの削除 |
| `git log --oneline` | コミット履歴の省略表示 |

### トピックブランチの作業フロー

```
1. git switch -c ブランチ名    ← ブランチ作成・切り替え
2. ファイルを編集
3. git add -A
4. git commit -m "メッセージ"
5. git switch main             ← mainに戻る
6. git merge ブランチ名         ← マージ
7. git branch -d ブランチ名     ← ブランチ削除
8. git push                    ← リモートに反映
```
