# 第6章：プッシュ後のやり直し

この章では、リモートにプッシュ済みの変更を安全に取り消す方法を学びます。やり直し操作の第3段階であり、第5章までの知識がすべてつながる章です。

---

## 6-1. 打ち消しコミットの作成 — git revert

### プッシュ済みの変更は「なかったこと」にはできない

第5章では `git reset` でコミットを取り消しました。しかし、リモートにプッシュ済みの変更に対しては、この方法は使えません。理由は2つあります。

- **履歴はすでに共有されている** — プッシュした時点で、その変更はリモートリポジトリに記録されています。ローカルの履歴だけを書き換えても、リモートには元の履歴が残ったままです。
- **他のメンバーが作業を続けている可能性がある** — プッシュされたコミットの上に、他のメンバーがさらにコミットを重ねているかもしれません。そこから履歴を消してしまうと、他のメンバーの作業との整合性が壊れます。

プッシュ直後にチームメンバー全員に「間違えたので待ってほしい」と周知徹底できるのであれば、`git reset` と強制プッシュで履歴を書き換えることは可能かもしれません。でも実際には、全員の作業を止めて確認を取ることは現実的ではありません。

そこで、プッシュ済みの変更は「消す」のではなく、「打ち消す」方法を使います。そのためのコマンドが `git revert` です。

### reset と revert の根本的な違い

第5章で学んだ `git reset` は、コミット履歴を「書き換える」操作でした。`git revert` は、過去のコミットの変更内容を打ち消す「新しいコミットを作る」操作です。

```
reset  : A → B → C → (resetでBに戻す) → A → B         ← 履歴からCが消える
revert : A → B → C → (revertでCを打ち消す) → A → B → C → C' ← 履歴にCは残り、打ち消しC'が追加される
```

履歴を壊さないため、プッシュ済みの変更でも安全に取り消せます。

---

### 実習：スモークベーコンバーガーの追加と取り下げ

#### 手順1：burgers.md に新メニューを追加する

burgers.md を開き、スパイシーチリバーガーのセクションの下（`---` と `[← トップに戻る]` の間）に以下を追加してください。

```markdown

## スモークベーコンバーガー

燻製ベーコンとスモークチーズの香ばしいハーモニー。BBQソースがアクセントの一品。

**¥1,500**

---
```

#### 手順2：コミットしてプッシュする

```bash
git add burgers.md
git commit -m "スモークベーコンバーガーを追加"
git push
```

#### 期待される出力（push部分）

```
To https://git-codecommit.<リージョン>.amazonaws.com/v1/repos/and-burger
   xxxxxxx..xxxxxxx  main -> main
```

> ここで「スモークベーコンバーガーの追加はまだ最終承認前だったので取り下げたい」という状況が発生した設定です。すでにプッシュ済みなので `git reset` は使えません。
>
> 「この変更を取り下げるので、revertします」とチームに連絡しました。では、実際のrevertの対応を進めていきます。

#### 手順3：コミット履歴を確認する

```bash
git log --oneline -3
```

#### 期待される出力

```
xxxxxxx (HEAD -> main, origin/main) スモークベーコンバーガーを追加
xxxxxxx 店舗情報を追加
xxxxxxx ドリンクメニューを追加
```

直前のコミット「スモークベーコンバーガーを追加」のハッシュ値を確認してください。

#### 手順4：git revert で打ち消す

```bash
git revert HEAD
```

エディタが開き、打ち消しコミットのメッセージが表示されます。デフォルトのメッセージのまま保存して閉じてください。

> **補足：** `HEAD` は直前のコミットを指します。`git revert コミットハッシュ` のように、ハッシュ値を直接指定することもできます。

#### 手順5：結果を確認する

```bash
git log --oneline -4
```

#### 期待される出力

```
xxxxxxx (HEAD -> main) Revert "スモークベーコンバーガーを追加"
xxxxxxx スモークベーコンバーガーを追加
xxxxxxx 店舗情報を追加
xxxxxxx ドリンクメニューを追加
```

> **補足：** 元のコミット「スモークベーコンバーガーを追加」は履歴に残ったまま、その変更を打ち消す新しいコミット「Revert "スモークベーコンバーガーを追加"」が追加されています。

#### 手順6：ファイルの内容を確認する

burgers.md を開いてください。スモークベーコンバーガーのセクションが削除されていることが確認できます。

#### 手順7：打ち消しコミットをプッシュする

```bash
git push
```

#### 手順8：CodeCommitのコンソールで確認する

ブラウザでCodeCommitのコンソールを開き、burgers.mdの内容とコミット履歴を確認してください。ローカルと同じ状態になっていることが確認できます。

### 振り返り：今やったことの流れ

```
1. スモークベーコンバーガーを追加した
2. 変更をリモートにプッシュした
3. 取り下げが必要になった
4. ローカルで git revert を実行した
5. revert のコミットをプッシュした
6. リモートの内容が修正された
```

ポイントは、元のコミットを消すのではなく、打ち消しコミットを追加してプッシュしたことです。履歴には「追加した」「取り消した」の両方が残るため、何が起きたかをあとから追跡できます。

## 6-2. reset と revert の使い分け

第5章と第6章で学んだやり直し操作を整理します。

### 判断基準：プッシュ済みかどうか

| 状況 | 使うコマンド | 理由 |
|---|---|---|
| プッシュ前 | `git reset` | 履歴を書き換えてもローカルだけなので問題ない |
| プッシュ後 | `git revert` | 履歴を壊さずに打ち消せるので、チームに影響しない |

### やり直し操作の全体整理

第2章・第5章・第6章で学んだやり直し操作を、状況別に1つの表にまとめます。

| 状況 | やりたいこと | 使うコマンド |
|---|---|---|
| コミット前・ステージング前 | ワークツリーの変更を取り消したい | `git restore ファイル名` |
| コミット前・ステージング後 | ステージングを取り消したい | `git restore --staged ファイル名` |
| コミット後・プッシュ前 | 直前のコミットメッセージを直したい | `git commit --amend -m "メッセージ"` |
| コミット後・プッシュ前 | 直前のコミットにファイルを追加し忘れた | `git add` → `git commit --amend` |
| コミット後・プッシュ前 | コミットを取り消したい（変更は残す） | `git reset --soft HEAD~1` |
| コミット後・プッシュ前 | コミットとステージングを取り消したい | `git reset --mixed HEAD~1` |
| コミット後・プッシュ前 | すべてを完全に巻き戻したい | `git reset --hard HEAD~1` |
| プッシュ後 | プッシュ済みの変更を安全に取り消したい | `git revert コミットハッシュ` |

> **補足：** 迷ったら「プッシュ済みかどうか」をまず確認してください。プッシュ前なら `reset`、プッシュ後なら `revert` が原則です。

## この章のまとめ

この章で学んだコマンドは以下の通りです。

| コマンド | 用途 |
|---|---|
| `git revert HEAD` | 直前のコミットを打ち消す新しいコミットを作成 |
| `git revert コミットハッシュ` | 指定したコミットを打ち消す新しいコミットを作成 |
